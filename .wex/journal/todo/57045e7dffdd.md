# Syrtis standardization — what the stack takes over, what Syrtis keeps

Opened: 2026-11-04
Updated: 2026-11-04
Author: agent:main

Survey of `SYRTIS/local/api` (≈900 PHP files) and `SYRTIS/packages/PHP/packages/syrtis/*` against the wexample stack, 2026-11-04. Four read-only passes: api layer, import/export, entity plumbing, Syrtis packages. Principle: the stack owns every mechanism; Syrtis declares (attributes, config, DTOs) and keeps only its domain. Each phase: package change first, with its own tests, then Syrtis rewritten on it, Syrtis' suite as the gate.

## 0. Security — before anything else (Syrtis only, small, urgent)

Found by reading config and code; to confirm over HTTP first.

- `/api/` lets anonymous requests through: `BearerTokenAuthenticator::supports()` is false without a header and `access_control` has no `^/api` rule. Unprotected as a result: `DefaultListPaginated` (~23 controllers, `CredentialController` included), `DefaultShowSecure*` (voter commented out), `DefaultDelete::deleteLegacy` (10 controllers, delete by id, no voter), `CollectionController::import`, `/api/test/*`, `V20261 SessionController::history`; `ApiInternalRoute` routes skip `denyAccessUnlessGranted`.
- 19 of 25 voters extend `AbstractLoggedUserEntityVoter`: any `ROLE_USER` views and edits any project's records. `AbstractProjectDependentVoter` asks VIEW on the project whatever the attribute: a watcher edits pipelines. DELETE allowed by no voter but one.
- Tokens stored in clear (`Token.value`), never expire, one more per login, never revoked.
- Swagger and `TestController` routed in every environment.

Fix: `access_control` `^/api/ → IS_AUTHENTICATED_FULLY` (public exceptions listed), project-scoped voters (§4.3 makes it generic), `/api/test` and nelmio `when@dev`, then tokens on symfony-api (§2.1).

- `src/Test/` → `tests/` (`App\Tests\`), off the production autoload.
- `UserConfig` → `symfony-preference` (already registered, one key/value store instead of three); `ApplicationRoleHelper` → `RoleHelper` + `security.role_hierarchy`; `HasParentVersionTrait` → `HasTargetTrait`; `findOneByIdentifier` → `findOneByDefaultIdentifier` (rides with the secureId removal, journal 906182dc63b5).

## 2. symfony-api — what it gains, then Syrtis on it

1. **Tokens**: Syrtis' `Token` → a subclass of `AbstractUserToken`, firewall on `UserTokenHandler`; migration hashes existing values (SHA-256 of the clear value + hint) so live clients keep working; `api:user-token:*` replaces ad-hoc issuing. New in symfony-api: a **password → token login endpoint** (`V20261/AuthController::login` is the case; options: scopes, lifetime, revoke previous) — or in symfony-user, to decide.
2. **Default entity actions**: the 14 traits of `Api/Controller/Entity/Traits` are generic (they only need symfony-api + helpers) and the filestate template already expects them in every app. Move into symfony-api as ~5 actions (list, show, create, update incl. title/position, delete), **voter check on by default**, lookup by id / identifier, `MapEntity` + `IsGranted(subject)`; normalizer from `EntityNormalizerRegistry`, repository from the manipulator → the 44 constructors, 69 `ROUTE_*` / 31 `DTO_*` aliases and the 3 show / 4 update / 2 delete variants collapse. List on `apiResponseQueryPage()` (total, sort whitelist) instead of `findPaginated` without total. Filestate template updated to use the package's.
3. **Dated versions**: `ApiVersionHelper` reads `/v<n>/` only; Syrtis uses `api/2026-1/`. Make the version pattern configurable (`v\d+` and `\d{4}-\d+`), so `versions:` Deprecation/Sunset, the journal's `api_version` and OpenAPI areas work for Syrtis; `App\Api\ApiVersion` / `SyrtisClient::API_VERSION_*` read one source.
4. **Small generic pieces**: partial DTOs (`UpdateTitle`, position XY, zoom) next to `AbstractDto`; "has more without a count" pagination probe (`fetchExtra` in session history); `orderBy`/`orderDirection` custom options → `#[SortQueryOption]` (today unwhitelisted into `queryField()`).
5. **Registry export**: `RegistryEntitiesSyncService` (488 l.) = `api:export:entities` + Doctrine metadata enrichment + default visibility: add the enrichment as an option of the command, delete the service.
6. **OpenAPI**: one area per dated version, `#[ApiResponseData]` where a client reads the data, nelmio routes `when@dev`, `ApiRoutePrefixTestCaseTrait` in Syrtis' suite. `ApiInternalRoute` puts internal routes under `/api/`: they belong under `/_api/` (route-prefixes norm) or behind a scope.

## 3. Import / export — a new package, `wexample/symfony-entity-transfer`

Syrtis' engine is ~60 % generic and lives in the app; no package covers it (`symfony-data-sync` is remote reconciliation, batch receipt is flat HTTP intake). The helpers `#[ImportableEntity]` attribute and the filestate templates already exist but point at app-local bases.

- Package takes: the abstract service (4-way relation resolution `_id` / `_<unique>` / `_ref` / inline, unique reuse, two-phase save/connect), `ReferenceHelper`, the references bags, locator, abstract and envelope DTOs/normalizers, relation validator, the 8 exceptions, command and test bases (round-trip test).
- Package adds what Syrtis lacks: **one transaction per root** (today every save flushes: an error mid-tree leaves a partial import), order from Doctrine metadata instead of hard-coded lists (deferred connect for cycles), **dry-run** + per-root report (batch receipt's outcome vocabulary), `formatVersion` in the envelope + **upcasters** (today `version` is written, never read; legacy shapes handled ad hoc inside services).
- Syrtis keeps: `#[ImportableEntity(unique:, children:)]` on 25 entities (replaces `ImportableEntityInterface` = 75 methods), the validation DTOs, hooks for the 4 services with real logic (Scenario, Slot, SlotConfig, SlotMessage); ~11 pure-boilerplate services and ~8 cascade services disappear; export normalizers mostly derived from the same metadata.
- **Hard constraint**: committed files (`assets/scenarios/system/*`, 141 test fixtures, prod dumps) keep importing — key names, `_ref`, `existing-<table>-<id>`. Gate: round-trip tests + re-import of every system scenario version, before and after. Add the 11 missing per-entity tests first.
- Depends on the planned `symfony-entity` / `symfony-normalizer` split (journal symfony-helpers 5e8bfe5a3b3b): sequence with it.

## 4. Entity plumbing — symfony-helpers and siblings

1. **symfony-helpers**: position repository trait (fixing its table-name bug: `strtolower(ShortName)` → ORM metadata) + renumbering after removal; stamp-collection sync (9 repositories); pgvector schema manager next to `VectorType`; `#[ForeignKeyOn]` (from `ContentTypeForeignKeysListener`); one-column traits (`HasDateCompleted`, `HasMetadata`, `HasEmoji`, width/height, zoom, version major/minor/patch).
2. **Elsewhere**: `Timezone` → symfony-geo; token price / carbon traits → symfony-ai-conversation; CSV / Markdown helpers → symfony-content, `PdfHelper` → symfony-pdf; `WithFixturesPathTrait` → symfony-testing; widgets → an `AbstractWorkspaceWidget` / `#[WorkspaceWidget]` in symfony-workspace (6 widgets differ by name and icon); `#[Searchable(routeParams:)]` in symfony-search (2 overrides go).
3. **Voters by declaration** (symfony-user or helpers): `#[EntityVoter(scope: 'project', path: 'pipeline.project', grants: …)]` → replaces 19 one-line voters and 3 project-dependent ones, and closes §0's gaps for good; form processors then use `isGranted(EDIT, $entity)` instead of 9 copies of `assertInScope`.
4. **Collapse**: 60 manipulator traits (identical) → convention resolver; 36 relation redeclarations → `#[ORM\AssociationOverrides]` or `#[LinkableEntity]` options; 6 `updateTitleByDto*` → one fallback; filestate rules applied where they are not (19 repositories without `createNew*`, 2 still on `ServiceEntityRepository`).

## 5. Messenger

8 per-queue serializers + 6 transport normalizers + `App\Message\AbstractEntityMessage` = what `symfony-messenger` ships (`EntityMessageSerializer`, pointer bodies). Bodies are full entities today and the Python core reads them: coordinate the format change with the core, behind a flag per queue.

## 6. Legacy api surface

`V20253` is mounted twice (`api/` and `api/2025-3/`) and the unversioned controllers with it; 55 `Legacy*` normalizers, 67 `@deprecated` files. Retire once no 2025 client (Drazen) reads them — `DrazenContractTest` pins what must stay until then. The same entity claimed by several normalizers in one tagged folder: check which one wins at runtime.

## 7. Syrtis clients

`php-client` stays (Syrtis-specific) on php-api-entity; its generic pieces move up: schema-dir loader with merge, repository discovery, the PHP entity/repository generators (duplicated byte for byte in `php-client-internal`). `symfony-client` builds its client through `symfony-remote` (one Syrtis client definition shared with symfony-translations; retries, status).
